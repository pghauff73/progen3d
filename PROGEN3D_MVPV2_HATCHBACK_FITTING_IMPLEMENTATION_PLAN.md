# ProGen3D MVPv2 Hatchback Fitting Implementation Plan

## 1. Objective

Promote the red AWD hatchback from an MVPv1 section-loft plus decorative panel-cut model to an MVPv2 spatial fitting model whose body and closures are described by evidence-bearing semantic objects.

The authoritative construction sequence is:

```text
Reference views
→ multi-view envelope
→ semantic cross-sections and surface landmarks
→ character-curve network
→ projection-constrained boundary patches
→ panel seam loops and extracted panels
→ apertures and closure assemblies
→ kinematic relationships
→ validated vehicle state and deterministic evidence
```

MVPv2 shall coexist with MVPv1. Existing `VehicleBodyShell`, `VehicleJoint`, examples, exports, and renderer paths remain legal while the richer object model is introduced.

## 2. Current Architectural Baseline

The current vehicle model provides:

- package, intent, datum, style, wheel, suspension, body, interior, exterior, and powertrain specifications;
- `VehicleBodySection`, represented as an arbitrary right-half profile at an axial station;
- `VehicleSurfaceGuide`, `WheelArchSpecification`, and `VehiclePanelCutSpecification`;
- one body-wide shell loft generated by `VehicleBodyAssemblyBuilder`;
- fixed, revolute, prismatic, and ball `VehicleJoint` declarations;
- deterministic assembly hashing and topology validation;
- grammar examples that lower semantic vehicle descriptions to existing FGKv1 geometry.

The missing responsibilities are:

- no semantic cross-section landmarks;
- no per-view observation/evidence model;
- no character-curve relationship graph;
- no patch boundary or patch continuity graph;
- no panel extraction or aperture model;
- no complete door, bonnet, hatch, or moving-glass assembly;
- no hinge-point pair, guide-rail, four-bar, or telescoping-link relationship;
- no closure dependency graph or swept-volume evidence;
- no deterministic hash over fitting and closure semantics.

## 3. P0 Promotion Boundary

P0 implements the full semantic and kinematic object model without attempting a production automotive Class-A surface optimizer.

P0 includes:

1. deterministic multi-view silhouette samples and weights;
2. semantic vehicle cross-sections;
3. observed surface landmarks;
4. named character curves and curve relationships;
5. boundary patches and projection constraints;
6. surface-patch edge continuity relationships;
7. seam loops and extracted panel records;
8. apertures with flange, seal, reinforcement, and mounting features;
9. complete side-door, bonnet, hatch, and drop-glass assemblies;
10. hinge pairs, four-bar joints, guide-rail joints, and telescoping links;
11. normalized closure state values;
12. deterministic transforms and sampled swept AABBs;
13. dependency validation, including door-local glass motion;
14. semantic validation and deterministic evidence hashing;
15. a researched red AWD hatchback acceptance fixture;
16. a grammar-facing example lowered to existing renderable primitives.

P0 deliberately excludes:

- nonlinear projection optimization of mesh control points;
- exact NURBS/Class-A patch evaluation;
- UV-domain Boolean panel extraction;
- exact collision meshes for moving closures;
- inferred hidden mechanism certification;
- production-grade four-bar synthesis;
- automatic landmark detection from images.

These exclusions are explicit rather than silently approximated.

## 4. Core Object Model

### 4.1 Multi-view evidence

```text
MultiViewEnvelope
├── ViewEnvelope
│   ├── view direction
│   ├── camera identifier
│   ├── silhouette samples
│   └── fitting weight
└── projection tolerance
```

Each silhouette sample owns a normalized image coordinate and a semantic label. Values are stored, not hidden behind callable functions, so they can be validated, serialized, compared, and hashed deterministically.

### 4.2 Semantic cross-sections

Replace arbitrary anonymous profile coordinates in new MVPv2 models with:

```text
VehicleCrossSection
├── station Z
├── centre roof
├── roof rail
├── glass shoulder
├── belt
├── upper shoulder
├── lower door
├── rocker
├── underbody
└── centre floor
```

Each landmark states its semantic role and local three-dimensional point. The section can derive an ordered right-half profile for compatibility with the existing body loft builder.

### 4.3 Surface landmarks

```text
SurfaceLandmark
├── semantic name
├── fitted 3D point
├── observed 2D points by view
├── confidence
└── evidence classification
```

Evidence classification distinguishes directly observed geometry from engineering/model inference.

### 4.4 Character curves

```text
CharacterCurveNetwork
├── CharacterCurve
│   ├── semantic role
│   ├── Curve3D
│   └── landmark identifiers
└── CharacterCurveRelationship
    ├── source curve
    ├── target curve
    ├── relationship type
    └── tolerance
```

Relationship types cover meeting, crossing, continuation, tangency, and termination.

### 4.5 Surface patches

```text
SurfacePatchGraph
├── BoundaryPatch
│   ├── four boundary curve identifiers
│   ├── internal guide identifiers
│   ├── normal constraints
│   └── projection constraints
└── SurfaceEdgeRelationship
    ├── source patch edge
    ├── target patch edge
    └── continuity type
```

Continuity types are:

```text
ContinuousC0
TangentG1
CurvatureG2
Crease
ShutLine
Aperture
```

`ProjectionConstrainedPatch` records initial patch identity, free landmarks/control points, view weights, continuity penalties, complexity regularization, and residual evidence. P0 validates and stores these constraints; a later solver may optimize them.

### 4.6 Panels and apertures

```text
PanelSeamLoop
├── host patch
├── closed boundary curve
├── gap width
└── gap depth

ExtractedSurfacePanel
├── source patch
├── seam loop
└── panel identifier

Aperture
├── host structure
├── outer boundary
├── inner boundary
├── flange depth
├── seal seat
├── reinforcement members
└── mounting interfaces
```

The semantic invariant is that a closure panel and its aperture refer to the same seam boundary rather than independently approximating adjacent geometry.

## 5. Closure and Kinematic Model

### 5.1 Unified closure assembly

```text
ClosureAssembly
├── closure type
├── host object
├── aperture
├── outer panel
├── inner panel
├── kinematic relationship
├── seals
├── hinges
├── latch
├── children
├── state
└── swept volume
```

Concrete closure types are side door, bonnet, rear hatch, and fuel flap. The model uses composition because each closure owns panels, interfaces, seals, and relationships; it does not use artificial inheritance for unrelated implementation details.

### 5.2 Hinge pair

`HingePair` stores upper and lower body-mount points. Its normalized axis is derived from those points. A zero-length pair is invalid.

Side-door transform:

```text
T(q) = Translate(pivot)
       Rotate(axis, q * maximumAngle)
       Translate(-pivot)
```

### 5.3 Four-bar joint

`FourBarJoint` stores two body mounts and two closure mounts. P0 derives a deterministic approximate panel transform from the interpolated hinge axis plus the average mount displacement. This is explicitly classified as an inferred engineering model.

### 5.4 Guide-rail joint

`GuideRailJoint` stores front and rear rail curves plus front and rear glass follower points. Evaluating both rails at the same normalized state determines translation and orientation.

The world glass transform is:

```text
T_world_glass = T_world_door * T_door_glass(q)
```

This dependency is mandatory and validated.

### 5.5 Telescoping link

`TelescopingLink` stores body mount, closure mount, minimum length, and maximum length. It validates bonnet supports and hatch gas struts across the closure state range.

### 5.6 Swept volume

P0 `SweptVolume` stores a deterministic union AABB sampled over a fixed ordered state sequence. The record includes sample count, minimum state, maximum state, local source bounds, and resolved swept bounds.

This is broad-phase evidence, not an exact swept solid.

## 6. Vehicle Aggregate

Add a new aggregate rather than overloading `VehicleBodySpecification` with unrelated responsibilities:

```text
VehicleFittingArchitecture
├── MultiViewEnvelope
├── VehicleCrossSections
├── SurfaceLandmarks
├── CharacterCurveNetwork
├── SurfacePatchGraph
├── PanelSeamLoops
├── ExtractedSurfacePanels
├── Apertures
├── ClosureAssemblies
├── DropGlassAssemblies
└── VehicleClosureState
```

`ModernVehicleAssembly` receives an optional immutable fitting architecture. MVPv1 builders may omit it. The MVPv2 red hatchback builder supplies it.

## 7. Validation Contract

`VehicleFittingValidationService` fails closed for:

- duplicate or empty identifiers;
- missing required front/side/top evidence;
- non-finite points, weights, tolerances, or state;
- out-of-range normalized coordinates and closure states;
- unordered cross-section stations;
- missing required cross-section landmark roles;
- invalid or missing curve references;
- invalid patch boundary count;
- missing patch references in continuity relationships;
- open seam loops;
- aperture boundaries that do not match panel seams;
- invalid hinge pairs;
- invalid four-bar mount geometry;
- invalid guide rails or coincident glass followers;
- invalid telescoping-link ranges;
- closure dependencies that reference missing parents;
- dependency cycles;
- moving glass that is not parented to its owning door;
- swept volume with non-finite or inverted bounds;
- inferred hidden hardware incorrectly marked as observed.

Diagnostics receive stable MVPv2 codes in `VehicleValidationReport`.

## 8. Determinism Contract

The same evaluated fitting architecture must produce identical:

- semantic object ordering;
- curve ordering;
- patch ordering;
- closure ordering;
- kinematic transform samples;
- swept bounds;
- validation report;
- deterministic hash.

`VehicleFittingDeterministicHashService` hashes evaluated values and semantic relationships. It never hashes object addresses, expression text, unordered containers, or locale-formatted strings.

The existing assembly hash remains available. MVPv2 adds a combined semantic evidence hash.

## 9. Grammar and Editor Integration

P0 keeps renderable geometry on existing FGKv1 shapes and adds a documented lowering pattern:

```text
MVPv2 semantic object
→ existing Object / Interface / Joint declarations
→ SurfaceLoft, ShellLoft, CurvedPanel, PanelCut, SweepDisk, and primitives
```

The grammar-facing acceptance example shall:

- use named body, door, bonnet, hatch, glass, hinge, latch, seal, and guide-rail objects;
- declare two-point hinge evidence as interfaces;
- preserve four moving door relationships;
- preserve bonnet and hatch relationships;
- express glass as door-contained objects;
- use current renderable geometry while documenting inferred hidden mechanisms;
- remain parseable by the current editor and supervisor mode.

The editor inspector can initially report MVPv2 data through generated evidence output. Native interactive patch/closure editors are post-P0.

## 10. Red AWD Hatchback Acceptance Fixture

The acceptance fixture contains:

- five view envelopes: front, rear, left, right, top;
- semantic transverse sections from front bumper to rear bumper;
- landmarks for wheel centres, arch apexes, lamp corners, bonnet corners, pillar bases, roof apex, door handles, hatch/spoiler, and rear lamps;
- character curves for roof, bonnet, belt, shoulder, lower-door crease, rocker, fender crests, rear haunch, and greenhouse boundaries;
- patches for bonnet, fenders, roof, four doors, quarters, hatch, and bumpers;
- four door closures;
- one bonnet closure;
- one rear-hatch closure;
- four moving side-glass assemblies;
- fixed windshield, quarter, and rear glass semantic children;
- bonnet support and hatch gas-strut links;
- a complete closure state.

The exact hidden regulator and hinge-linkage geometry is marked `EngineeringInference`.

## 11. Test Matrix

### Model tests

- required view coverage;
- semantic section landmark completeness;
- landmark view observation consistency;
- curve and patch reference integrity;
- seam-loop closure;
- aperture/panel boundary agreement;
- duplicate identifier rejection.

### Kinematic tests

- hinge axis derived from two points;
- door closed state is identity;
- door open state reaches configured angle;
- glass rail state follows both rails;
- glass world transform composes through door transform;
- four-bar state is deterministic;
- telescoping links stay within limits;
- swept bounds contain every sampled transformed corner;
- dependency cycles fail.

### Acceptance tests

- red AWD hatchback model validates;
- expected patch, closure, and glass counts match;
- all normalized closure states are valid;
- repeated construction produces identical semantic hash;
- altered state changes the semantic hash;
- all hidden mechanisms carry inference provenance;
- the renderable grammar example parses and exports;
- supervisor screenshots are captured from stable views.

## 13. Merge-Equivalent Milestones

### Milestone 1 — semantic fitting kernel

Implement multi-view evidence, semantic sections, landmarks, curve networks, patch graphs, seams, panels, and apertures.

Gate: invalid references and missing evidence fail deterministically.

### Milestone 2 — closure and kinematic kernel

Implement closure assemblies, hinge pairs, four-bar joints, guide rails, telescoping links, state, dependencies, and swept bounds.

Gate: all ten closure/window state channels evaluate deterministically.

### Milestone 3 — vehicle aggregate and evidence

Integrate optional fitting architecture into the vehicle aggregate and add semantic hashing.

Gate: MVPv1 remains source-compatible and MVPv2 hashes are stable.

### Milestone 4 — red AWD hatchback fixture

Build the full semantic fixture and current-grammar rendering example.

Gate: expected objects, patches, closures, windows, provenance, and state validate.

### Milestone 5 — visual and supervisor evidence

Run source checks, grammar parsing, export, and supervisor-mode views.

Gate: no upside-down transforms, no unexpected collision placement, and stable front/rear/side/top framing.

## 14. Definition of MVPv2 P0 Complete

MVPv2 P0 is complete when:

```text
multi-view evidence exists and validates
semantic body sections exist
surface landmarks exist
character curves form a validated network
body patches form a validated graph
panel seams and apertures share boundaries
four complete door closures exist
one bonnet closure exists
one rear-hatch closure exists
four guide-rail glass assemblies exist
door-local glass dependency is enforced
hinge axes derive from point pairs
four-bar and telescoping relationships are represented
closure state evaluates deterministically
swept broad-phase bounds are recorded
hidden mechanisms are marked as inference
semantic hash is stable
MVPv1 remains compatible
the red AWD hatchback fixture passes
the renderable example passes grammar checks
visual evidence is captured
```

The central rule is preserved throughout:

```text
Do not fit disconnected parts independently.
Fit one constrained vehicle system, extract closures from its continuous body,
and move those closures through explicit semantic relationships.
```
