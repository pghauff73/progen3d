Progen3D Vegetation Grammar Implementation Plan

1. Objective

Reading guide: this source section records “1. Objective”. Distinguish stated behavior from proposed or pending work using the status styling.

Implement vegetation as a first-class Progen3D subsystem whose canonical flow is:

PlantSpecies + Development State + Environment
    -> BranchGraph
    -> Organ Placements
    -> Procedural Geometry + Shared Instances
    -> Spatial Validation + Resolution Evidence

The subsystem must not encode a tree as unrelated cylinders and spheres. Botanical topology, geometry, development, environmental reasoning, and rendering detail remain separate object-model responsibilities.

3. Phase V0A - topology kernel

Reading guide: this source section records “3. Phase V0A - topology kernel”. Distinguish stated behavior from proposed or pending work using the status styling.

Implement:

  1. BranchNode with stable identifier, position, radius, age, branch order, and state.
  2. BranchSegment with one parent and one child node.
  3. Bud, GrowthTip, and OrganAttachment as semantic records.
  4. BranchGraph with one root, unique node identifiers, directed parent-child edges, organ attachments, buds, and growth tips.
  5. BranchGraphValidationService enforcing finite values, positive radii, a valid root, one parent per non-root node, reachability, acyclicity, increasing branch order, and attachment references.
  6. BranchRadiusConservationService checking parentRadius^gamma ~= sum(childRadius^gamma) with species tolerance.

V0A gate

Reading guide: this source section records “V0A gate”. Distinguish stated behavior from proposed or pending work using the status styling.

  • Valid trunk/branch/twig graph passes.
  • Duplicate identifiers, cycles, disconnected nodes, invalid radii, and invalid attachment references fail with stable diagnostics.
  • Traversal order is deterministic.

TaperedSweep

Reading guide: this source section records “TaperedSweep”. Distinguish stated behavior from proposed or pending work using the status styling.

Add a procedural shape family containing a path, one radius per path sample, an up hint, radial tessellation, cap policy, and detail level. Generate parallel-transport frames, continuous taper, hard end caps, deterministic UVs, semantic surface tags, collision acceleration, and a canonical cache key.

BranchJunction

Reading guide: this source section records “BranchJunction”. Distinguish stated behavior from proposed or pending work using the status styling.

P0 constructs a deterministic local transition assembly from parent and child sweep sections plus a junction bulge. The result is explicitly classified as compound geometry until a watertight implicit/SDF blend is implemented.

LeafBlade and PetalBlade

Reading guide: this source section records “LeafBlade and PetalBlade”. Distinguish stated behavior from proposed or pending work using the status styling.

Use a shared botanical blade abstraction with concrete leaf and petal specifications. The mesh is generated from a longitudinal centreline, width law, camber, twist, base/tip shape, thickness, and deterministic tessellation. Thickness greater than zero must create a closed mesh; a zero-thickness blade is an intentional surface.

  • Repeated specifications produce identical keys, vertex order, triangle order, and topology hashes.
  • Bounds, normals, UVs, volume evidence, and collision policy are valid.

11. LOD and instancing contract

Reading guide: this source section records “11. LOD and instancing contract”. Distinguish stated behavior from proposed or pending work using the status styling.

LOD0 Bounds              crown/root proxy
LOD1 CoarseShape         trunk and crown clusters
LOD2 Assembly            major branches and leaf clusters/cards

Expressions are retained during parsing and evaluated during grammar expansion. Mesh generation consumes evaluated values and performs no random sampling.
