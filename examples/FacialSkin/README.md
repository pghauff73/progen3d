# Native facial skin: milestone A

This example introduces the native `FacialSkin` primitive. It constructs one
connected, procedurally authored front-face surface with separate eye and mouth
openings, then evaluates localized expression fields from immutable rest
coordinates. It contains no imported character mesh.

The implementation is a **geometric facial rig**. Its expressions are not an
elastic tissue solve, calibrated muscle simulation, or a replacement for Lyra's
existing complete head. This standalone study establishes the topology,
controls, native grammar integration, and validation needed for that work.

## Native syntax

```text
Start -> I(FacialSkin(size(0.16 0.21 0.045) segments(48 64)
           smile(0.7 0.7) jawOpen(0.25) blink(0 0)
           browRaise(0.2 0.2)) material(softpinkmatteplaster) 1 1)
```

The study uses metres, +Y up, +Z forward, and +X as the character's anatomical
left. `size` supplies width, height, and front-surface depth. Paired controls
always use **left, right** order, independently of the camera's viewpoint.
The checked-in `Lyra_Facial_Study.p3d` is ready to open after building a version
of the editor that includes this primitive.

| Option | Meaning | Accepted values |
|---|---|---|
| `size(w h d)` | Overall procedural patch dimensions | Each dimension in (0.00001, 1000]; height/width in 0.5–2; depth/width in 0.05–1 |
| `segments(x y)` | Stable parameter-grid resolution | X multiples of 48 in 48–192; Y multiples of 64 in 64–256 |
| `smile(left right)` | Mouth-corner and cheek deformation | Each value in 0–1 |
| `jawOpen(value)` | Lower-face and lower-lip deformation | 0–1 |
| `blink(left right)` | Upper/lower eye-margin closure | Each value in 0–1 |
| `browRaise(left right)` | Independent brow-region lift | Each value in 0–1 |

All control arguments use the existing native expression evaluator, including
rule parameters and `t` in seconds. Invalid controls are rejected rather than
silently clamped. Supported resolutions retain the same semantic aperture
locations, while vertex counts change with resolution. Topology stays fixed
while expressions change at a chosen resolution.

## Build and test

Follow the repository's `BUILDING.md` dependency instructions and use fresh
objects after changing public geometry headers.

```sh
make -j2 build/form-study-sample build/facial-skin-test
make facial-skin-check
```

The native harness checks the generator and validator. The Python study checks
actual grammar parsing and evaluation through `form-study-sample`, rejects
invalid controls/segments/options, and measures the exported triangle geometry.
The existing native build workflow runs both.

## Create the visual study

```sh
python3 examples/FacialSkin/face_study.py \
  --sampler build/form-study-sample \
  --out build/facial-skin-study \
  --timeline-frames 37
```

Outputs include:

- `Lyra_Facial_Study.p3d`: a native six-second expression cycle.
- `Lyra_Facial_Study.html`: a self-contained visual inspector of native samples.
- `validation.json`: topology, gap, normal, neutral-return, and seek evidence.
- `study.json`: native sampled positions, normals, controls, and landmarks.
- `samples/`: independently runnable grammars and OBJ geometry for each pose.

The inspector supports front, three-quarter, and profile views; orbit/zoom;
named poses; a sampled timeline; wireframe; landmarks; and schematic smile
direction guides. It displays the supplied native samples without implementing
a second facial deformer or interpolating between poses. Shared indexed mesh
assets keep the default 46-sample inspector near 7.2 MB. Packing verifies exact
reconstruction after the existing display rounding; geometric acceptance
checks use the full native export precision. Only the selected sample is
expanded for rendering.

Eye and dark oral geometry are illustrative procedural scene objects. Iris
and pupil surfaces are native spherical caps concentric with the eye globes,
so they follow the curved surface beneath the lids. Display colors are a
diagnostic palette, not a validated skin shader.

`form-study-sample` now exports evaluated native UV coordinates and normals as
well as positions. Its `facial_landmark` comments are generated by the same
native model as the skin, so the study does not duplicate landmark equations.

## Validation and limits

The end-to-end check requires one connected skin component, four topological
boundary loops (outer perimeter, two eyes, mouth), no nonmanifold edges or
branched boundaries, positive front triangle winding, nonzero triangle area,
unit normals, and positive lid and mouth clearance. It checks constant vertex
and triangle counts across poses, repeated out-of-order time queries, and
return to neutral after one cycle. Tiny lid/lip clearances intentionally retain
separate margins and avoid degenerating the skin topology.

The native harness also screens every triangle against both eye globes across
all 128 combinations of the seven controls at their endpoints, including the
aperture rims. It checks that deformed vertex normals face the same way as
their triangles, maximum supported detail, and uniform miniature scaling.
This bounded contact regression does not prove clearance for every intermediate
control, dimension ratio or resolution. At default dimensions, a fully closed
blink deliberately retains approximately 0.168 mm of vertical aperture.

The initial default-size validation produced these results:

| Measurement | Result |
|---|---|
| Skin vertices / triangles | 3,034 / 5,712 |
| Connected skin components / boundary loops | 1 / 4 |
| Binary endpoint combinations of seven controls | 128 passed |
| Smallest triangle-to-globe gap in that sweep | +0.01256 mm |
| Neutral / fully blinking vertical aperture | 18.375 mm / 0.168 mm |
| Native visual cases | 9 named poses + 37 timeline samples |
| Repeated-time / end-of-cycle position error | 0 m / 0 m |

The standalone inspector's data decoder and interaction logic were exercised
with a mocked DOM/WebGL interface. A native Blender rendering was visually
reviewed. Actual browser GPU execution and mobile-browser layout remain
unverified; the development environment could not launch its browser.

This milestone rebuilds the small native surface for each evaluated pose and
does not retain an unbounded cache of animated face variants. A persistent
deformation buffer and performance profiling are future work.

An optional annotated still can be rendered from the same exported samples:

```sh
blender -b --python examples/FacialSkin/render_study.py -- \
  --study build/facial-skin-study --output build/facial-skin-study/Facial_Study.png
```

These are geometric acceptance gates. They do not establish anatomical
accuracy, tissue force, local volume conservation, general collision safety,
or frame-time performance. The model is an open front-face patch; it does not
include a back cranium, complete oral cavity, teeth, tongue, or full Lyra
identity fitting. The old full Lyra skin must be replaced or cut before this
surface can be integrated without filling the new apertures.

Next development should add explicit attachment/material maps, distributed
muscle specifications, calibrated lid/lip contact, and a deterministic elastic
simulation timeline after these geometric controls are accepted.
